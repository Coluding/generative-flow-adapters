The sharding audit

Run this against any preprocessing stage before splitting it across machines. Designed to print on two sides.

1. The test

Shardable ⟺ every output depends only on inputs inside its own shard. Everything else is deferred to a merge that runs once, over the whole set.

2. Three questions

#QuestionGrep forIf yes
1Statistic — does an output need records outside this one? .mean( .std( min max set( Counter sort dedup Shards emit raw/local values → merge aggregates once
2Identifier — does it allocate names/indices/keys used downstream? enumerate _{i} uuid count id = Merge reassigns globally; assert uniqueness
3Ordering — does anything downstream depend on position? [0] first [:n] index idx Fix a deterministic concat order; assert it

All three "no" → shard it. Any "yes" → that piece moves to the merge.

3. Silent-failure catalogue

The reason to audit rather than to test-and-see: none of these raise.

Missed couplingWhat you getGuard that catches it
Per-shard normalization N inconsistent feature scales; training converges to something wrong Merge refuses input that is already normalized (action_mean present)
Per-shard identifiers Key collisions → downstream lookups return another record's value Assert len(set(ids)) == len(ids) after merge
Order assumed, not fixed Position-keyed caches alias to the wrong item Compare a prefix against a known single-pass run
A shard died A quietly smaller dataset; every metric still computes --expect-shards / --expect-episodes
Relative paths not rebased FileNotFoundError — the one loud failure of the set Merge stats every referenced file

5. Glossary

Global couplingA computation whose correct value requires the entire dataset. Deferred, never distributed.
ShardA disjoint subset of the input, processed by one independent task. Shards must partition: no gaps, no overlaps.
MergeThe single pass that resolves every deferred coupling and emits the canonical manifest. The reduce.
Spanwindow_width × frame_stride — frames one training window consumes. Episodes shorter than the span are dropped (data/dataset.py:69).
Cache keyenv|episode_idx|start_idx|frame_stride|t×h×w → sha1[:20].pt (data/latent_cache.py:27). Any component changing invalidates; episode_idx is why order matters.
Fixed startsThe deterministic pool of ≤ num_windows evenly-spaced window starts per episode. Determinism is what makes caching possible.

6. Slurm array cheat sheet

#SBATCH --array=0-17          # 18 tasks; add %6 to cap concurrency
#SBATCH --array=0-17%6

K=${SLURM_ARRAY_TASK_ID}      # this task's index
PER=$(( (TOTAL + N - 1) / N ))    # ceil division
BEG=$(( K * PER )); END=$(( BEG + PER )); [ $END -gt $TOTAL ] && END=$TOTAL

sacct -j <arrayjobid> --format=JobID,State -X    # one row per index
scontrol requeue <jobid>_7                       # re-run a single index

Node packing is not controlled by --array. Slurm may place many tasks on one node and they will contend for cores — observed 2.5× rate spread (155 vs 61 eps/min) across the RT-1 array. Use --ntasks-per-node or a concurrency cap if even pacing matters. Primary source: SchedMD, Job Array Support.
